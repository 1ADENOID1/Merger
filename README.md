## Описание
- Утилита предназначена для автоматизированного слияния настроечных json файлов клиента с файлами дистрибутива, которые поставляются по умолчанию  
- Основной принцип слияния файлов - значения из клиентских файлов имеют приоритет над значениями из файлов дистрибутива, независимо от смысла параметра (Утилита не знает об их значении и это не входит в её задачи)  
- Результат слияния сохраняется в клиентских файлах, потому перед слиянием делается резервная копия клиентских файлов. Это гарантирует сохранность пользовательских настроек в исходном состоянии  
- Также утилита не требует вмешательства или каких-либо действий оператора в процессе работы. Для начала работы требуется лишь задать в конфигурационном файле необходимые параметры  
- Различная структура клиентского файла и файла дистрибутива (соответствие файлов определяется по совпадении их относительного пути и имени с расширением .json) не является помехой для слияния. Недостающие в клиентских файлах поля будут автоматически подтянуты из файла дистрибутива (см. правила слияния)  

## Правила слияния файлов
1. Если в дистрибутиве появилось новое поле - оно добавляется в клиентский файл со значением из дистрибутива
2. Если в дистрибутиве отсутствует поле, но присутствует в клиентских файлах (или удалилось в дистрибутиве) - оно сохраняется в клиентском файле (со значением клиента)
3. Массивы рассматриваются как примитивный тип при слиянии. То есть при слиянии массивов сохраняется его содержимое из файла клиента (в будущем планируется добавление слияния на уровне массивов)
4. Если в клиентском файле значение поля примитивного типа данных или пустой объект {}, а в соответствующем файле дистрибутива данное поле содержит не пустой объект, то в клиентском файле сохраняется его примитивное значение, вложенные поля в файле дистрибутива игнорируются
5. Аналогично п. 4 в обратной ситуации, когда в клиентском файле значение поля не пустой объект, а в файле дистрибутива примитивный тип данных или пустой объект, то в клиентском файле сохраняется его вложенный объект, примитивное значение из файла дистрибутива игнорируется
6. При возможности, порядок полей сохраняется в том порядке, в котором он был до слияния
7. Перед слиянием утилита (при парсинге файлов) производит валидацию файлов. В случае, если какой-либо файл имеет некорректную структуру или возникла ошибка файлового ввода-вывода - в консоль выводится сообщение об ошибке и утилита прерывает свою работу
8. Утилита рекурсивно обходит переданные ей директории с клиентскими файлами и директории с файлами дистрибутива (включая вложенные директории) и "собирает" все файлы, имеющие расширение .json. Файлы с другим расширением или без него будут проигнорированы. Если исходных директорий (клиентская или дистрибутива) не существует или они являются не папкой, а файлом, то будет выведено сообщение об ошибке и работа утилиты завершится
9. В случае, если файл в клиентской директории не существует, но существует его "пара" в директории с дистрибутивом (то есть по тому же относительному пути и имени файла, что и в директории дистрибутива), то утилита его создаст в клиентской директории и перенесёт в него все поля из соответствующего файла дистрибутива
10. В случае, если файл в директории дистрибутива не существует, но существует его "пара" в директории с клиентскими файлами - утилита оставит клиентский файл нетронутым
11. Если директория с клиентскими файлами пустая - утилита перенесёт в него все файлы из директории с файлами дистрибутива, если директория с файлами дистрибутива пустая - утилита ничего не будет делать. Аналогично если обе директории пустые
12. Если в файле в клиентской директории корневым элементом является массив, а в файле в директории дистрибутива корневым элементом является объект, то в клиентском файле останется массив. В обратном случае в клиентском файле останется объект. Если в обоих файлах корневой элемент массив, то в клиентском файле будет сохранено значение клиента
13. Считается, что клиенту поставляется дистрибутив, содержащий только его ресурсы (директория resources, которая передаётся утилите в параметре запуска DISTR_DIR), аналогично клиентские файлы содержат только те ресурсы, которые принадлежат клиенту

## Сборка и запуск
**Внимание:** Для работы утилиты необходимо сконфигурировать файл config.env
Для запуска утилиты на компьютере должны присутствовать JDK 11 или новее (разработка велась на JDK 11, работоспособность на ранних версиях не гарантируется) 
- Для сборки проекта необходимо запустить build.bat (Windows) или build.sh (Linux/MacOS)  
- Для запуска утилиты необходимо запустить start.bat (Windows) или start.sh (Linux/MacOS)
  
## Настройки start.bat
1. UPDATED_RES_DIR - Абсолютный путь к директории с конфигурацией дистрибутива (в дистрибутиве это директория resources, содержащая json файлы)  
2. CURRENT_RES_DIR - Абсолютный путь к директории с пользовательской конфигурацией  
3. BACKUP_DIR - Абсолютный путь к директории, в которую будет производиться бэкап пользовательских файлов перед началом работы утилиты  
4. CREATE_BACKUP_SUBDIR - Режим бэкапа пользовательских файлов: 
    - true - создать поддиректорию backupN (где N - номер папки, если она дублируется) по пути из параметра BACKUP_DIR и выполнить бэкап в неё, 
    - false - не создавать поддиректорию, выполнить бэкап в директорию из параметра BACKUP_DIR. **Внимание:** для режима false обязательно, чтобы директория, указанная в параметре BACKUP_DIR была пустой 
5. CREATE_CHANGELOG - записывать лог изменений в файл changelog.txt, который будет генерироваться в директории утилиты
    - true - записывать лог изменений
    - false - не записывать лог изменений
	> Разработка данной функции ещё не завершена, возможна некорректная работа	
6. FILE_ENCODING - Кодировка файлов. По умолчанию UTF-8 (является стандартом для json). Необязательный параметр

### Пример конфигурации config.env (Windows)
```
UPDATED_RES_DIR=C:\\resources
CURRENT_RES_DIR=C:\\resources1
BACKUP_DIR=C:\\userBackup
CREATE_BACKUP_SUBDIR=true
CREATE_CHANGELOG=true
FILE_ENCODING=UTF-8
```

### Пример конфигурации config.env (Linux/MacOS)
```
UPDATED_RES_DIR=/resources
CURRENT_RES_DIR=/resources1
BACKUP_DIR=/userBackup
CREATE_BACKUP_SUBDIR=true
CREATE_CHANGELOG=true
FILE_ENCODING=UTF-8
```
